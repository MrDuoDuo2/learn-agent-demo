# 本地聊天页面设计

## 目标与范围

在 `web/` 下创建一个独立的 Vue 单页应用，用于演示本地聊天记录管理。

- 用户可以新建、切换和删除会话。
- 用户输入内容后，页面仅追加一条用户消息。
- 会话和消息在浏览器刷新后仍然存在。
- 本期不调用 `backend/`，不生成模拟助手回复，也不修改 FastAPI。

## 技术方案

采用 Vue 3、Vite 和 TypeScript。状态直接由 Vue 的组合式 API 管理，并通过 `localStorage` 持久化；当前只有一个页面和一套状态，不引入 Pinia 等额外状态库。

选择这套方案的原因是工程小、启动快，且将来接入聊天接口时，只需替换发送消息的处理逻辑，不需要重做页面或历史记录结构。

## 页面结构

页面为适合持续操作的两栏布局：

1. 左侧会话栏：包含“新建会话”按钮、按更新时间排序的会话列表，以及每个会话的删除操作。
2. 右侧聊天区：顶部显示当前会话标题，中部滚动显示消息，底部固定多行输入框和发送按钮。
3. 空状态：没有会话时，引导用户新建会话；当前会话没有消息时，提示输入第一条内容。

窄屏时，会话栏默认收起为可打开的抽屉，聊天区保留完整可用宽度。

## 数据模型

浏览器的 `localStorage` 使用单个命名空间键保存以下数据：

```ts
type Message = {
  id: string
  role: 'user'
  content: string
  createdAt: string
}

type Conversation = {
  id: string
  title: string
  createdAt: string
  updatedAt: string
  messages: Message[]
}

type ChatStore = {
  activeConversationId: string | null
  conversations: Conversation[]
}
```

会话标题在第一条消息发送后取其前若干个字符；没有消息时使用“新对话”。所有写入操作完成后立即同步到本地存储，读取失败或格式不合法时回退为空状态，避免页面无法打开。

## 交互流程

1. 用户点击新建会话，应用创建一个空会话并将其设为当前会话。
2. 用户输入非空内容，按 Enter 发送；按 Shift+Enter 换行。
3. 应用生成消息 ID 和 ISO 时间戳，将用户消息追加到当前会话，更新会话标题与更新时间，并写入 `localStorage`。
4. 消息区滚动到底部。由于本期无后端，消息发送后没有助手消息或加载状态。
5. 用户删除当前会话后，应用选中最近更新的剩余会话；若无会话，显示空状态。

## 组件边界

- `App`：组织布局、管理响应式状态和持久化。
- `ConversationSidebar`：展示与选择会话，触发新建和删除事件。
- `ChatPanel`：展示当前会话的消息和空状态。
- `MessageComposer`：管理输入内容、键盘行为和发送事件。

组件通过 props 和 emits 传递数据及意图，不在子组件中直接读写 `localStorage`。

## 后续接入后端

未来可将发送逻辑抽为 `sendMessage(content, conversation)` 服务：先保留用户消息，再调用后端聊天接口，并把响应转为 `role: 'assistant'` 的消息。持久化格式预留了 `role` 字段，因此不影响已经保存的本地记录。

## 验收标准

- 开发服务器能启动并显示聊天页面。
- 新建、切换、删除会话均可用。
- 发送后只出现用户消息。
- 刷新浏览器后，会话、消息和当前会话仍能恢复。
- 在桌面和窄屏下，输入、发送和查看历史都不会发生布局遮挡。
